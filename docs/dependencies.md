# Dependency selection evidence

Official Flutter and package-publisher documentation was checked on 2026-10-16 before selection. Direct dependencies are exact pins; `pubspec.lock` is generated by the selected Flutter SDK and must be committed. Future upgrades require paired review and CI. Publisher package pages are authoritative for their own packages; the ML Kit Flutter bridge is community maintained, not a Google-maintained Flutter SDK.

Flutter framework and `flutter_test` are SDK-pinned. The app's Dart floor is 3.12 and Flutter floor is 3.44; development and CI use the exact newer SDK above. No PostgreSQL credentials, JWT signing keys, or backend secret config belong in this repository. `API_BASE_URL` is a public build-time endpoint, not a secret.

The secure-storage publisher README still includes a version-10 notice mentioning Android API 23. Inspection of the resolved **11.2.0** package's `android/build.gradle` confirms `minSdk = 24`; the application uses that actual stricter requirement.

The resolved transitive `jni_flutter` 1.0.4+1 plugin compiles with Android SDK 35 while the application compiles/targets SDK 36. Gradle installs the additional platform and CMake 3.22.1 during the first build if SDK licenses are accepted. The generated Flutter app uses NDK 28.2.13676358.

The application enforces HTTPS outside debug mode in its Dart API configuration. Android also has a debug-only [domain network security configuration](https://developer.android.com/privacy-and-security/security-config) for local endpoints. The Dart restriction matters because [Flutter-owned sockets do not inherit every native network policy](https://docs.flutter.dev/release/breaking-changes/network-policy-ios-android). The standalone local smoke script intentionally allows loopback HTTP.

## Planned camera adapter, not implemented or installed

Current candidates are [`camera` 0.12.1](https://pub.dev/packages/camera/versions/0.12.1) and [`google_mlkit_pose_detection` 0.16.1](https://pub.dev/packages/google_mlkit_pose_detection/versions/0.16.1). Verify these again when implementing, pin together with generated lock changes, and exercise the actual Android image-stream conversion path. `camera` requires Android API 24+ and delegates app lifecycle handling to the application. The community ML Kit wrapper's current Dart requirement is ≥3.12.

Google's [native Android pose detection guide](https://developers.google.com/ml-kit/vision/pose-detection/android) documents the pose API as beta and requires Android API 23+. Choose the stricter app/camera baseline of API 24. Native pose confidence, landmark visibility, and timestamp handling need device validation; simulated confidence values do not validate ML performance. Beta native APIs and third-party wrapper changes are a Day 1–2 integration risk, not a reason to expand sprint scope.
